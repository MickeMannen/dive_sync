        How to edit the board
      
A sync run writes one side: the board shows what the target accepts from the source (⇄ shows the other direction). To add a rule either drag a field from the left-hand list onto a field on the right, or — easier over a long list — click the left-hand field once, then click the right-hand field to take it. Do the same onto a field that already has a rule to build a composite. Drag the same text field onto a second field to split it: e.g. Activity name onto Location and then onto Dive site takes "Gozo, Blue Hole" apart into both. Click a rule to change its policy or template. Locked fields cannot be written by their service; fields without a rule are not synced.

Garmin dives

      
The dives the last refresh cached from Garmin Connect, and whether each one's original .fit has been downloaded. FIT files are saved under data/garmin_fit/ with the same name as the dive's cached JSON: <dive #>_<date>_<time>_<activity id>. Dives marked manual were logged by hand: they have no dive-computer file (Garmin would only generate a summary-only FIT from the typed-in fields), so they are never downloaded.

Default sync settings

      

        
        
        
        
        
        
        
        
      

      
Propagate deletes: delete the linked dive on the other side when one is deleted here. Only ever acted on during a full sync - an incremental (only-new) run has no reliable way to tell "deleted" apart from "outside this run's date window", so it never deletes on an incremental run regardless of this setting.

      
Create on Garmin: off by default. A dive found only on the other side is created on Garmin only when this is on; matched-dive field updates are never affected. Uploads the other way (to Divelogs, or to a non-Garmin pair) are unaffected either way.

    


    

      
Failure alerts

      
A webhook POSTed a short plain-text message when a scheduled or manual sync run fails. Works with ntfy (paste your topic URL, e.g. https://ntfy.sh/your-topic) and most generic webhook receivers; Gotify needs its endpoint to accept a raw text body.
