# Sync

Pick a **source** and a **target** (⇄ swaps them) and press **Sync now**. Options: *Dry run*, *Only new dives*, *Sync gases*, *Mirror* (make the target a copy of the source; asks for confirmation) and *Use cached Garmin dives*. With several accounts for a service, pick which one to sync with next to the source and target (remembered). **Download dives** stores each service's dives on this computer for its Dives page (only the picked accounts); the run log is below. When a run finishes but the target refused or could not do some of its writes (an update it did not take, a dive it could not add), the status line says how many dives failed instead of "Sync complete." - the log says which and why, and nothing is marked done that was not.

**MySSI** (beta) is a source and a target like the others once an account is saved on [Settings](settings.md), with its own **MySSI account** picker when there are several; a note under the Source/Target row says what the beta means. Towards MySSI a sync **adds new dives only**: a dive already on MySSI is matched (by the sync history, by the dive-computer reference DiveSync sent with it, or by its start time) but changes to it are not sent, and the log says so for each such dive, until updating has been tested; a dive with two or more tanks is skipped with a line saying why; and **no sync run deletes on MySSI** - not Mirror, not a pair with propagate deletes on: the run logs each dive it would have deleted, counts it as skipped and leaves it (a MySSI delete is permanent, and the dive number may not come back); only the MySSI Dives page deletes there. Reading MySSI is one request for the whole logbook, so **Download dives** for its Dives page is quick. The connection is the MySSI app's own, unofficial one, which SSI can change or close at any time.

**New Garmin dives as .fit (beta)** shows when Garmin is the target. Ticked, a dive the run creates on Garmin Connect is uploaded as a `.fit` file written from the dive, the same file the Dive edit page's **Save as .fit** writes, so its profile, tanks, gases and the computer's per-sample values arrive in Connect; unticked (the default) Garmin gets a manual activity with the summary only, as before. The name, notes, buddy, weight, visibility and location are set on the new activity right after the upload; what neither holds (a suit, an air temperature, tank roles other than a diluent, ...) is named in the log. A dive without a profile is still sent as a manual activity. The box only changes *how* a dive is created: creating new dives on Garmin at all is the pair's **Create on Garmin** option on the [Mapping](mapping.md) page (or *Mirror*). The new activity is linked at once, so the next run does not send it again; if Connect answers that it already has the file, the dive is counted as skipped, not failed. A dry run lists the dives it would upload and what each `.fit` would leave out. Try it with a dry run, then on one dive, before a whole log.

A sync started from this page never deletes unless *Mirror* is ticked. What a run does with each field is decided by the pair's [mapping board](mapping.md); the same engine runs from the [command line](cli.md) and the [Docker image](docker.md).
