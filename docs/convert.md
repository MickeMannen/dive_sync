# Dive edit

## Opening files

The **Dive edit** page (formerly Convert) works on files, not accounts: open one or several Garmin `.fit` files (a watch's own dive file, or Garmin Connect's "export original" zip), UDDF files or Subsurface `.ssrf` files (`.xml` is accepted for both; the content decides), and the page lists their dives on the left with, on the right, an editor for the dive clicked - its summary, tanks, depth profile and the extra channels the file holds (tank pressures per transmitter, NDL, time to surface, deco stops, CNS, PO2, heart rate, gas switches and alerts, the dive computer and its gradient factors). A file that is not a scuba dive (another Garmin activity, an apnea dive) is reported under the file list and skipped. Select the dives (click one, Cmd/Ctrl-click adds or removes one, Shift-click a range, **Select all**) and **Save as UDDF…** or **Save as Subsurface…**: one dive goes through a Save-as dialog, several give one file per dive (`<date> <time> dive <number>.<ext>`, a `(2)` suffix when the name is already taken) in a folder you pick. Before you save, the page says what the chosen format cannot hold: UDDF has no slot for the time to surface, water type, bottom time or exit position; Subsurface rates visibility with stars and has no GF99 channel. UDDF is what Subsurface, Submersion, MacDive and divelogs.de import; `.ssrf` opens directly in Subsurface. Depths, temperatures, tank sizes and pressures, weight and visibility - and the depth profile's axis - are shown in the unit system chosen under **Units** on the Settings page; the files you save are metric whichever units are shown.

## Editing a dive

Click one dive and every field the app holds for it is on the card, in groups: **Dive** (date, time, time zone as a UTC offset such as `+07:00`, duration, max and average depth, bottom time, water temperature min/max/avg, surface interval, dive mode, water type, water density), **Site** (name, entry and exit position), **People / notes** (buddy, weight, visibility, notes), **Dive computer** (maker, model, serial, firmware, gradient factors, deco model, CNS start and end) and **Tanks / gases** (a table with name, O2, He, volume, start and end pressure and role; **+ Add tank** and ✕ remove a row). A change takes effect when you leave the field (Tab, Return or a click elsewhere): the dive in the list updates at once and the Save buttons write the dive with its edits; the file you opened is never changed, and the events of the dive are shown but not editable. On a dive recorded by a computer the duration and the max and average depth come from the profile and are read-only (labelled so); on a hand-logged dive they are editable. Changing the date, time or time zone moves the whole dive - every profile sample and event keeps its place in the dive and so moves with the start - while the duration stays. A value the app cannot take (a depth that is no number, a dive mode outside the known words, a wrong time zone) is refused with a message under the card and nothing changes. Quantities are typed in the units chosen on the Settings page and stored metric at full precision; a field you did not touch is kept exactly as the file had it, so a rounded display never changes the data. A dive with edits you have not saved yet carries a dot (●) in the list and "● edited" on its card; **Revert** puts it back as it was read from the file - or as you last saved it - without touching the file on disk, and with several dives selected "Revert N" reverts the edited ones among them. Saving a dive (as UDDF, Subsurface or .fit) clears its mark; a save that fails keeps it. **Remove**, **Clear** and closing the app ask first ("Discard edits to N dives?") when a dive with unsaved edits would be lost; opening more files keeps the marks.

## The profile

Move the mouse over the depth profile and the sample nearest the pointer is marked with a line and a dot, with a tooltip beside it: the time into the dive, the depth and the water temperature; the no-decompression limit left, or in deco the next stop's depth and time and the time to surface; the gas breathed (Air, EAN32, O2, a trimix as O2/He, with the tank's name when the dive has more than one tank) and each tank's pressure by its name; CNS, PO2, setpoint, heart rate and the gas time remaining - only the lines the dive computer logged at that sample, in the units chosen on the Settings page. A click pins the tooltip at that sample (a diamond at the top of the line; click again or press Esc to unpin), and with the chart focused the Left and Right arrow keys step through the samples one at a time (Shift for ten), pinning as they go. A gas switch is marked with a tick and the gas name above the profile, and when the computer logged a deco ceiling the profile is shaded from the surface down to the next stop.

## Save as .fit

Every dive can be saved as a Garmin `.fit`, in one of two ways depending on where it came from.

**A dive opened from a Garmin `.fit`** (or from Connect's zip around one) is saved back with its edits by patching: **Save as .fit…** writes a copy of the watch's own file in which only the values you changed are rewritten - the file is patched in place, field by field, and every other byte stays exactly as the watch wrote it, so Garmin Connect, Subsurface and any other reader take the copy like the original. The suggested name is `<original name> (edited).fit` beside the original; the file you opened is never overwritten (choosing its name is refused), and several selected dives give one patched file per dive in a folder you pick. What goes into the file is what a FIT holds: the start time and time zone (every timestamp in the file moves with the start), dive number, bottom time, surface interval, CNS start and end, entry and exit position, each tank's gas (O2, He), start and end pressure and size, gradient factors, water type and density, dive mode and the average water temperature. What no `.fit` holds - site, buddy, notes, weight, visibility, the deco model and computer texts, a tank added on the page - is listed under the buttons before you save ("Not in a .fit, save as UDDF or Subsurface for these: …") and left out; the min and max water temperature of a recorded dive come from its profile samples and are not rewritten either.

**Any other dive** - from a UDDF or Subsurface file, hand-logged or recorded by another computer - is written as a new Garmin `.fit` from scratch, with Garmin's own FIT SDK: a dive activity file with the computer (a Garmin model is named by its product number, the serial and firmware when they are numbers), the deco settings (ZHL-16C, gradient factors, water type and density), one gas per tank, every profile sample with its depth, temperature, tank pressures, NDL, time to surface, deco stop, CNS, PO2, gas time and heart rate, the gas switches and Garmin's alerts, the tank summaries with names and sizes, the dive summary (number, bottom time, surface interval, CNS, depths), the entry and exit position, the water temperatures and the time zone. The suggested name is the usual `<date> <time> dive <number>.fit` in the folder of your last save, and several dives give one file each. The line under the buttons lists what the dive holds that no `.fit` can: site, buddy, notes, weight and visibility, a deco model other than ZHL-16C, the maker and model of a computer that is not a Garmin (the file says Garmin either way, as every `.fit` does), a serial or firmware that is not a number, a tank's role, the GF99 and setpoint channels, mode-change, setpoint and bookmark events, and a Subsurface rating, tags, suit or divemaster.

The button is on for a selection of either kind and off, with a tip saying why, for a selection that mixes dives from a `.fit` with others (the names and the drops differ; select one kind at a time). Garmin Connect knows a dive by its start time and device: delete the original activity there before uploading an edited file, or Connect will refuse it as a duplicate. Whether Connect accepts a `.fit` written from scratch - a file no Garmin watch recorded, stamped with Connect's own product id when the dive's computer is not a Garmin - has not been verified yet.

## Merge a split dive

Sometimes a dive computer splits one dive into several logs: a short surface stop ends the first log and a new one starts when you descend again. Open the logs (two or more, Garmin `.fit` or Connect's zip - `.fit` logs only), select them in the list (Cmd/Ctrl-click adds one, Shift-click a range) and click **Merge…** at the bottom of the list, under the hint line: it is on as soon as two or more dives are selected (its tooltip and the line next to it say what it does; with fewer selected the tip says to select two or more). The dialog lists the selected logs in start order, whatever order you clicked them in - date, time, dive number, duration and file of each, the first fixed and the later ones ticked; untick one to leave it and every log after it out (a chain cannot skip). When the selection cannot be merged the dialog says why in red and Save… stays off: a dive from a UDDF or Subsurface file (named), logs from different dive computers, two that overlap, or two more than 2 hours apart; untick the odd one and the reason clears. It offers two ways to join the logs:

- **Add the surface time**: the surface time between the logs stays in the dive, filled with the previous log's last sample. Every log keeps its clock times, so photos and videos from every log still line up with the merged dive, and the dive ends when the last log did.
- **Remove the surface time**: the surface time is taken out; each later log moves back so it follows the previous one without a break, as one continuous dive that ends earlier than the last log did. Photos and videos from the later logs no longer match the log.

**Save…** asks where to put the merged log (it suggests `<first log's name> (merged).fit` next to the first one; a name equal to one of the logs is refused, the reason shown under the list) and adds the merged dive to the list, selected, with the merged file as its source - a normal dive from then on: edit it, save it as .fit, UDDF or Subsurface, remove it. The merged dive starts when the first log did and ends when the last did, lists the gases of every log, carries the tank readings of every transmitter and the GPS, heart rate and other data the computer logged; the first log's file is kept byte for byte and only its summaries are updated. The originals stay in the list and are never changed. The merge reads the files on disk, so an edit you have not saved yet is not in the merged file - the dialog flags such a row and says to save it as .fit first. Garmin Connect knows a dive by its start time and device, so it treats the merged log as the first dive: delete all the original activities there before uploading it.

The merged file carries the dive computer's serial, which Garmin Connect uses to tell which watch a file came from. The app reads it from the file's header and, when the header leaves it out, from the file's device record. When a selected log still has no serial the dialog shows **Dive computer serial for the merged file** with the serials of the logs being merged to choose from (the first log's is preselected when it has one) and says which log lacks one; the chosen serial is written into the merged file. When no log has a serial at all the dialog says so and the merge goes ahead without one - Garmin Connect may not accept such a file. Logs that carry two different serials are two computers, not one split dive, and are still refused.

When the dialog refuses a selection, or a merge fails with an error under the list, **Generate debug report…** next to the reason saves a text file you can send to the developer: the app, system and library versions, the merge that was asked for, why it was refused or how it failed, and for each log its file name, size and checksum, the dive computer and its serial, start and end times, sample count, gases, tanks and event counts, plus the app's recent log lines. It holds no GPS positions, site or location names, notes, buddy, full file paths (file names only; your home folder is written as `~`), passwords or tokens, and says so at the top; it is written only to the file you pick.

## The list and the Garmin cache

The list is a working list: **Open files…** adds the files' dives to it (a dive already in the list - from the same file, or with the same start time and dive number - is skipped and counted in the message), **Open folder…** adds every dive file directly in a folder you pick - by extension (`.fit`, `.zip`, `.uddf`, `.ssrf`, `.xml`, upper or lower case), in name order, hidden files left alone, and only the top folder: subfolders are not searched; a file that turns out not to be a dive file is named under the list as with Open files…, and a folder with nothing to read says so in one line - **Remove** (or the Delete/Backspace key on the list) takes the selected dives off it, **Clear** empties it. Only the list changes; the files on disk are never touched. **Open Cached** is the same Open dialog started in the `.fit` files this app has downloaded from Garmin Connect for the Garmin page's account (they sit in the app's data folder, which is hard to find by hand); it leaves the folder the Open and Save dialogs remember alone. The button is off, with a tip saying why, until a Garmin account is set up and the Garmin page's Download dives has cached something.

A Garmin `.fit` whose dive is in the app's Garmin cache (the dives the Garmin page has downloaded) is filled in from there - site, buddy, notes, weight, visibility and tank sizes, which the watch's file does not hold - only where the file has none; a tank size the watch wrote (set on the computer for the SAC) stays the watch's. The cached dive is found by the activity id in the file's name (the app's own cache names, `<n>_<date>_<time>_<id>`, and the names Connect exports, `<id>.zip` holding `<id>_ACTIVITY.fit`) or, when the name holds none or no cache has that id, by the start time: the cached dive starting within two minutes (a renamed file such as `515.fit`, or one kept in your own folders). With several Garmin accounts an exact id match wins, then the account the Garmin page shows, then name order. The dive's pane says what was filled, from which account, and whether it was matched by start time; the **Fill from Garmin cache** checkbox (on by default, remembered) switches it off. Nothing is read from or written to any online account; the dialogs open in Documents the first time and then in the last folder used.
